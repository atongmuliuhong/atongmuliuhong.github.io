市场主体调查技能：签合同前，先把对方查清楚

一句话结论：市场主体调查技能：签合同前，先把对方查清楚

问：做律师、做生意的，大概都遇到过这种时刻：一份合同摆在面前，条款谈得差不多了，签字笔也拿起来了，心里却还悬着一件事——对面这家公司，到底是个什么底细？
它是不是真的存在，注册资本多少，法人是谁，有没有被执行，有没有进过失信名单。这些事，过去要一个个平台翻，翻完还不一定对得上。现在可以交给一个技能：市场主体调查技能。

把"查公司"这件事标准化

它的入口很朴素：给它一个企业简称或者全称，它先做一次模糊搜索，把要查的主体锁定下来，再按你指定的维度，一条条取回结构化的数据。

数据来自风鸟 Fengniao（Riskbird）。和自己在搜索引擎里翻网页不同，这里返回的是对齐过的工商和风险字段，不是一堆需要你自己拼的链接。

能查哪些维度

先看工商信息这一侧：企业基本信息（法人、注册资本、成立日期、统一社会信用代码、注册地址、经营范围）、股东信息、董事监事高管、对外投资、工商变更。

再看风险这一侧：被执行人、失信被执行人、限制高消费、经营异常、严重违法、行政处罚。

这两侧合起来，就是一份企业尽调最常要的那张表。需要的时候，它还能把已支持的维度整合成一份尽调报告。

怎么用：先找维度，再查主体

顺序不能反。它要求先想清楚要查哪个维度，再去搜公司。

第一步，按维度发现工具：

discover "企业股东信息"

第二步，模糊搜索企业，拿到它的内部标识：

call biz_fuzzy_search --params '{"key":"某某公司"}'

第三步，用这个标识去查具体维度：

call biz_shareholders --params '{"entid":"……"}'

一次主体解析之后，多个维度复用同一个标识，不用反复搜。

几条规矩，比"能查什么"更要紧

这个技能最值得说的地方，不在能力列表，而在它给自己划的几条线。

第一，主体消歧是必须的。如果给的是一个简称，或者这个名字本身有歧义，它不会假设唯一、直接开查，而是先跟你确认是哪一家。查错主体，比查不到更糟。

第二，结果只用工商登记全称。列表里不会出现简称，避免张冠李戴。

第三，内部标识不外露。它内部用来串联各维度查询的那个 ID，对使用者没有意义，结果里不展示。

第四，只展示真实返回的数据，不编造。某个维度没有记录，就直接说没有；某个维度还没接入，就明说当前版本暂不支持。结构化接口的结果和网页搜索的结果，会分开标注来源，不混在一起。

对一个要拿去做决策的工具来说，这几条比多接几个维度重要得多。

配置与边界

用之前需要先准备一把钥匙：在风鸟的 Web 端生成个人 API Key，配置成环境变量 FN_API_KEY。完整 Key 只在创建时展示一次，要留意保存。

有两点提前说清楚。一是额度：多个 Key 共用同一账号的每日额度，多建 Key 并不会多给次数，实时额度以风鸟后台为准。二是报错：Key 没配或失效、当日额度用尽，都会明确提示；查不到记录也会直说，不会拿一堆空字段来充数。

END

查清楚，不等于不信任。恰恰是查清楚了，合作才敢往深里走。
